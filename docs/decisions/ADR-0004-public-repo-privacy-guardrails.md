# ADR-0004: Public repo with privacy guardrails from day one

Date: 2026-09-05 · Status: Accepted

## Context

trippy is research code that will be useful to others (porting TRIPS to Apple Silicon, training on custom data, hybrid Gaussian+neural-point rendering). Publishing it accelerates adoption and allows feedback. However, Jordan's family photos and scene captures must never be public. This creates a tension: we want an open-source repo, but we must prevent accidental leaks of private data.

Three approaches exist:

1. **Private repo forever**: no leak risk, but blocks external collaboration and reproducibility.
2. **Public repo, no guardrails**: maximal openness, high leak risk (renders, videos, PLY files can be committed by mistake).
3. **Public repo with guardrails**: open from day one, with automated checks preventing large files, images, and private scenes from being committed.

## Decision

Adopt **Option 3**: public MIT-licensed repo on GitHub from the first commit, with automated guardrails built into hooks and CI.

## Guardrails

### Pre-commit hook (automated block)

A `pre-commit` hook refuses to stage or commit:

- **Large files** (>5 MB): catches checkpoint files, trained models, scene archives.
- **Extensions**: `*.png`, `*.jpg`, `*.jpeg`, `*.mp4`, `*.ply`, `*.pt`, `*.pth`, `*.ckpt`, `*.safetensors` (images, videos, point clouds, model files).
- **Paths**: anything under `output/` or `third_party/` (prevents accidental commit of training artifacts).

The hook is installed by `scripts/bootstrap.sh` and enforced by `.githooks/pre-commit`.

### AGENTS.md public-repo rule

Section §12 (PUBLIC-REPO rule) states plainly:

> This repo is public. No photo, render, contact sheet, video, PLY, or checkpoint from Jordan's scenes may ever be committed. Place names are fine; people (faces) never. When an example image is needed, use the public Zenodo TRIPS scene.

This rule is explicitly taught to all agents; breaching it is a refusal condition.

### Synthetic test fixtures only

All test data, if visual, is synthetic (generated by code):
- 32×32 random point clouds for kernel validation.
- Synthetic COLMAP models for geometry tests.
- No photos from Jordan's scenes in `tests/`.

### Deliverables live outside the repo

All finished artifacts (contact sheets, renders, dolly videos, exported PLY files) go to:

```
~/Splats/output/Jordan-Review/
```

This folder is **private** (owned by Jordan, not in any public repo). Artifacts are delivered via `scripts/deliver.sh` and referenced in release notes, but the actual files are never committed.

### Reproducible public example

For outsiders to validate the codebase:

- Use public Zenodo TRIPS scene (record 10687419, CC-BY 4.0).
- `tools/fetch_upstream.sh` clones TRIPS and links to Zenodo (but does not download without `--download` flag).
- Reproducibility documentation includes steps using only public data.

## Consequences

### Transparency

- Anyone on the internet can review the algorithm, train it on their own data, and improve it.
- Bugfixes and improvements can be contributed via pull requests.
- Jordan maintains editorial control (merge decisions) while benefiting from the community.

### Privacy

- Pre-commit hook prevents accidental leaks automatically (no human vigilance required).
- Delivery workflow ensures Jordan's scenes stay in the private review folder, not in version control.
- If a breach ever happens (e.g., via force-push), git history can be cleaned by the maintainer without loss to the repo's integrity.

### Verification

- `scripts/push.sh` re-runs the pre-commit file guard before pushing to ensure the full push range contains no forbidden files.
- Release notes include a link to `docs/UPSTREAM.md` (attribution and license compliance).

## Related

- `.gitignore`: excludes `output/`, `third_party/`, `*.pth`, etc.
- `scripts/review.sh` includes a checklist step to verify no renders are being committed.
- `docs/UPSTREAM.md` and `docs/USER_GUIDE.md` explain the privacy model to users.
