# trippy — TRIPS on Apple Silicon: spec + build plan

## Context

Jordan's Gaussian splats of outdoor family scenes have one defect that five training-side fixes failed to remove:
the shade under trees becomes a dark cloud you walk through, not a lighting effect. On the TRIPS paper's own
side-by-sides, 3DGS shows this defect and TRIPS does not. trippy is a new, separate project that ports TRIPS
(Trilinear Point Splatting, MIT) to this Mac Studio, trains it on Jordan's scenes, hybridises it with Gaussians,
and ships live viewers (Mac + web), with a distilled-splat fallback for the Quest. Nobody human edits the code:
LLM agents (Claude or Codex) run the repo under LLM-agnostic rules copied from the sibling Revisit project.

Outcome wanted: Jordan steps into a Karekare scene in a viewer and the shade is shading. Everything else is signal.

## Technical design (PyTorch/MPS)

Principle: all per-point differentiable math in vectorised PyTorch (autograd gives position/size/confidence/pose/intrinsics grads free); only the sorted, order-dependent compositing in Metal. No atomics anywhere.

Forward per image: project (torch, learnable SE(3) delta on COLMAP pose) → emit ≤8 fragments per point (2 pyramid levels × 2x2 bilinear; alpha = bilinear × sigmoid(conf) × layer_factor; drop out-of-bounds, never clamp) → sort by (layer,pixel,depth) via int64 argsort (fallback: two stable 32-bit sorts, Brush's pattern) → segment offsets → **`blend_fwd` Metal** one thread per layer-pixel, front-to-back over, cap 16, writes features, T_final, expected depth → U-Net (torch) → tone mapper → losses (L1 + SSIM + LPIPS/VGG16).

Backward: **`blend_bwd` Metal** writes per-fragment d_alpha, d_feat; `index_add_` reduces to points; autograd carries the rest. Wrapped in `torch.autograd.Function`.

Validation (CPU pytest, before any GPU job): xform_a vs xform_b agreement + reprojection of COLMAP points3D onto stored keypoints (~1 px, depth positive); numpy reference vs Metal forward on 32x32 (<1e-5) incl. >16-fragment pixels and border cases; float64 gradcheck via `ref_torch`, then Metal grads vs ref (<1e-3); padding test (no fragment outside crop); U-Net odd-size shape test. `xform_a` also drives the dolly renderers so drift shows as misaligned sheets.

Point sources: `GaussianPlySource` (centres, f_dc colour, size from Gaussian scale or kNN-4, conf from opacity), `MonoDepthSource` (reuse `~/Splats/tools/ldi/depth_batch.py` at prio 10-19, median-ratio scale align to sparse depths, voxel dedupe), `UnionSource`, `LidarSource` stub. Per-point provenance uint8 carried through training. `export.py` writes 3DGS-compatible PLY so `depthprior_shade_audit.py`, `extent_gate.py`, `gsrender.py`, Brush viewer run unchanged on TRIPS point sets.

Hybrid (v0.3): (C) render→photo U-Net refinement on `gsrender.py` outputs first (cheap, validates net/losses); (A1) Gaussians as TRIPS points with learned feature vectors, joint training; (A2) EWA footprints backlog; (B) distillation after Brush exists (near-path cameras only, honesty rule).

Honesty sheet per candidate: raw level-0 composite | network output | coverage/provenance map; pixels with raw coverage <0.3 outlined in the network image.

## Risks (honest) and mitigations

- **Point density holes** in exactly the shade region: source 2/3 densify there; report blank-coverage fraction per view before training; simple low-coverage point spawning in backlog.
- **U-Net hallucination**: honesty sheet mandatory; "fixed" requires the raw composite to walk through the shade cleanly too.
- **MPS**: no 64-bit atomics (designed around); int64 argsort at 50M unverified (fallback ready); non-contiguous tensors fail silently in compile_shader (assert); no float64 on MPS (CPU gradcheck); allocator watermark (log memory).
- **Training time**: A100 2-4 h → 30-60 h here at paper settings; use half-res, crop 384, fewer epochs, profile epoch 1 and extrapolate; overnight jobs at prio 70.
- **Metal debugging**: tiny kernels, numpy/torch twins, standard `dbg` buffer, 8x8 tests first.
- **Perceptual loss** differs from TRIPS's caffe-VGG: note, don't chase.
- **Extent inflation**: free positions; run extent gate on every export; soft AABB penalty from day one.
- **Brush toolchain**: pinned wgpu/cubecl forks; forward-only in Rust first; U-Net conv speed on Burn is the fps risk (levers: fp16, net at 0.75 scale, fragment cap).
- **Quest**: ~120 GFLOP/eye/frame is not interactive on a mobile GPU; measure once, ship distilled fallback.
